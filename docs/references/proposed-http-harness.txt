Spec: Multi-Provider Agentic Prompt Cache Benchmark Harness
Build a standalone benchmark CLI that measures prompt cache reliability, latency, and cost overhead across Gemini, Anthropic, and OpenAI from the perspective of an external developer calling public APIs.

The harness must run identical multi-turn agentic loops against all three public HTTPS endpoints using standard customer API keys, and report both turn-level cache reliability and dollar cost vs. a theoretical perfect cache.

1. Non-Negotiable Principles (Customer Parity)
2. Direct Public HTTPS Only: Call public REST endpoints directly (https://generativelanguage.googleapis.com, https://api.anthropic.com, https://api.openai.com). Do not use internal proxies, Vertex AI, or first-party GCP projects.
3. External Paid-Tier Keys: Use a standard external Paid Tier API key for each provider (for Gemini, a GCP project without GOOGLE_INTERNAL labels).
4. Byte-Deterministic Payloads: JSON serialization must preserve key and array order (sort_keys=False on ordered dicts, fixed tool ordering, no timestamps or random IDs inside prompt text except an intentional per-trial cold-start nonce).
5. No Provider Lock-In SDK Magic: Use thin HTTP requests (e.g., httpx in Python or fetch in TypeScript) so exact wire payloads, headers, SSE timing, and usage fields are logged without SDK mutation.

3. Workload Design: Three Diagnostic Modes
To separate pure server routing/eviction issues from prompt-mutation bugs and diverging model outputs, implement three workload modes (--workload-mode):

1. replay (Identical-Prompt Control): Sends the exact same multi-turn prompt on every turn $t \in [1..20]$ without growing it. Any cache miss in replay proves pure server-side routing, metro switching, or KV eviction.
2. append (Plain-Text Growth): Appends a fixed plain-text user/assistant turn pair of delta_tokens on each turn, with no tools. Isolates incremental checkpoint advancement without tool or thought formatting variables.
3. agent (Tool-Call Loop, Default): Realistic multi-turn coding-agent loop with tool calls and tool results. Supports both Deterministic Replay (default, using recorded assistant tool calls) and Live Generation (temperature: 0, max_output_tokens: 128).
Prompt Structure & Gemini-Specific Pitfalls
- System Prompt (~4,500 tokens): Realistic coding-agent instructions.
  - Cold-Start Nonce: In intra_session mode, prepend Session-Nonce: <uuid4> at line 1 of the system prompt on Turn 1 (and keep that exact UUID for all turns of that trial). This guarantees Turn 1 is a cold cache write and isolates intra-session retention.
  - Shared-Prefix Mode: In cross_session mode, omit the nonce (or use one shared batch nonce across trials) and vary only Turn 1's user prompt across trials to test cross-session shared system/tool prefix hits.
- Custom Tool Declarations (~4,500 tokens): 20 realistic JSON Schema functionDeclarations (e.g., read_file, edit_file, run_command, search_code, git_diff, etc.). Combined with the system prompt, Turn 1 starts at ~9,000 tokens (safely above Gemini's 6,000-token floor, Anthropic's 1,024–4,096 floor, and OpenAI's 1,024 floor).
- Avoid Built-In Tools in the Default Arm: Do not enable Gemini built-in tools (googleSearch, urlContext, fileSearch, googleMaps, computerUse) in the default benchmark arm. On Gemini, built-in tools inject a server-side "Current time is <minute-resolution timestamp>." block immediately before the last user turn, which changes every 60 seconds and breaks prefix caching across 30s and 120s gaps. (Support an optional --enable-builtin-search flag if testing that specific behavior.)
- Preserve thoughtSignature on Gemini (agent mode): On Gemini thinking models, the response hides raw thought tokens and attaches an encrypted thoughtSignature field to functionCall and text parts. When replaying prior model turns in contents, the harness must echo back thoughtSignature unchanged on every model part. Dropping thoughtSignature prevents the server from restoring cached thought tokens (triggering EmptyThoughtInjector fallback) and causes an artificial prefix miss at the prior model turn. Notice that because thoughtSignature is encrypted per response, multi-turn agent loops on Gemini thinking models must run in Live Generation mode (or replay responses originally generated within that same Gemini session).
- Multi-Turn Trajectory (20 turns per trial):
  - Each turn $t \in [1..20]$ in agent mode appends:
    1. Assistant tool call (preserving thoughtSignature on Gemini, tool_use blocks on Anthropic, and function_call items on OpenAI).
    2. User / Tool result block of configurable size (delta_tokens).

6. Metrics & Formulas to Report
Compute metrics over follow-up turns ($t \ge 2$) for intra_session, and over trials ($k \ge 2$) for cross_session.
A. Hit Rate Metrics (Show All Three)
1. Strict Full-Hit Rate (Turn-Level):
  - A turn $t \ge 2$ is a Full Hit if cached_read_tokens(t) >= total_prompt_tokens(t - 1) - tolerance_tokens (default tolerance_tokens = 64 for role-formatting markers).
  - Formula: COUNT(Full Hit turns) / COUNT(turns where t >= 2).
  - Note: Also report the rate at tolerance_tokens = 2100 to show how many Gemini turns only missed "Full Hit" because of the 2,050-token recovery window.
2. Any-Hit Rate (Turn-Level):
  - Fraction of turns $t \ge 2$ where cached_read_tokens(t) > 0.
3. Token-Weighted Hit Rate:
  - Formula: SUM(cached_read_tokens) / SUM(total_prompt_tokens).
4. Reusable-Prefix Capture Rate (Roofline Efficiency):
  - Formula (for $t \ge 2$): SUM(cached_read_tokens(t)) / SUM(total_prompt_tokens(t - 1)).
B. Cost vs. Perfect Cache (1.00x Baseline)
Use a configurable rate card (pricing.yaml with input_per_mtok, cache_read_per_mtok, cache_write_per_mtok, and long_context_threshold_tokens = 200000).

- Actual Input Cost (Turn $t$): $$\text{Cost}{\text{actual}}(t) = \text{uncached_input}(t) \cdot R{\text{in}} + \text{cache_write}(t) \cdot R_{\text{write}} + \text{cached_read}(t) \cdot R_{\text{read}}$$
- Perfect Cache Input Cost (Turn $t$):
  - Turn $t = 1$: $\text{total_prompt_tokens}(1) \cdot R_{\text{in}}$ (no prior prefix exists in the session).
  - Turn $t \ge 2$: Let reusable prefix $P(t) = \text{total_prompt_tokens}(t - 1)$ and new delta $\Delta(t) = \max(0, \text{total_prompt_tokens}(t) - P(t))$. $$\text{Cost}{\text{perfect}}(t) = P(t) \cdot R{\text{read}} + \Delta(t) \cdot R_{\text{in}}$$
- Cost Multiplier vs. Perfect Cache: $$\text{Cost Multiplier} = \frac{\sum_{t=1}^{T} \text{Cost}{\text{actual}}(t)}{\sum{t=1}^{T} \text{Cost}_{\text{perfect}}(t)}$$ (Also report Cost Multiplier (t >= 2) excluding Turn 1 cold start so both views are visible.)
C. Latency Metrics (Streaming SSE)
- ttft_ms: Wall-clock milliseconds from sending the HTTP request body to receiving the first SSE chunk containing a non-empty content/thought/tool delta (p50, p90, p99).
- total_turn_ms: Wall-clock milliseconds until the stream finishes.

7. Required Outputs & Verification
1. Per-Turn Raw Log (runs/<run_id>/turns.jsonl):
  - One JSON record per turn containing: run_id, provider, model, workload_mode (replay / append / agent), session_mode (intra_session / cross_session), idle_gap_seconds, delta_tokens, trial_id, turn_index, timestamp_utc, http_status, response_id (Gemini responseId for Sherlog lookup, OpenAI/Anthropic id), trace_headers (x-goog-request-id, request-id, cf-ray), ttft_ms, total_turn_ms, prev_total_prompt_tokens, total_prompt_tokens, cached_read_tokens, cache_write_tokens, uncached_input_tokens, output_tokens, cost_actual_usd, cost_perfect_usd, is_full_hit_strict, is_full_hit_2100_tol, and raw_usage_json.
2. Summary Report (runs/<run_id>/summary.md & summary.csv):
  - Side-by-side table grouped by (provider, model, idle_gap_seconds, delta_tokens) showing:
    - Turns ($t \ge 2$), Strict Full-Hit %, 2.1K-Tolerance Hit %, Any-Hit %, Token-Weighted Hit %, Reusable-Prefix Capture %, Cost Multiplier vs. Perfect Cache, and p50/p90 TTFT.
3. Self-Tests (Unit Tests Required Before Running Live):
  - Unit test token normalization with real fixture responses from Gemini (usageMetadata), OpenAI (prompt_tokens_details), and Anthropic (cache_creation_input_tokens + cache_read_input_tokens + input_tokens).
  - Unit test the Cost vs. Perfect Cache formula: verify that a synthetic trace where every turn $t \ge 2$ reads 100% of total_prompt_tokens(t - 1) from cache produces an exact 1.00x multiplier (when $R_{\text{write}} = R_{\text{in}}$).
  - Unit test byte-determinism: calling the payload builder twice for Turn $t$ produces byte-identical JSON up to the Turn-$t$ prefix.
