# Focused small context protocol

Registered after the eight-call replay qualification and before the focused allocation. This replaces the proposed 46,080-call grid with a 134-call screening allocation plus eight qualification calls. It cannot estimate a provider-wide miss frequency or reproduce Theo's sample size. The supplied server-side explanations and thresholds are hypotheses, not established facts.

The primary comparison is Gemini Flash 3.8 and Gemini 4 Argon at about 8K initial tokens: identical replay versus deterministic growing messages, two independent trials of eight requests each at a five-second completion-to-next-request gap. Growing messages target 1.5K added tokens so the trajectory should cross 16,384 actual input tokens. Real API usage, not character labels, determines whether it crossed. A tool-loop arm preserves actual model output, including native signatures and encrypted reasoning. Additional Gemini arms test about 4K replay, 600/3,000-token tool deltas, and a 32K starting prefix. GPT-6.1 Sol and Opus 5.5 provide smaller replay/tool-loop controls.

The eight qualification calls used 32,000 prefix characters: Flash reported 8,952 initial input tokens and Argon 8,976. Their average determines a single characters/token allocation for all models; tokenizer differences and actual inputs are reported. Qualification is retained separately, never pooled. Opus's two qualification responses were refusals with zero output and repeated cache writes; they are not evidence of successful task completion or a healthy control. The planned Opus arms remain visible without changing their prompt/settings or silently replacing that model.

The synthetic reference-record content comes from the existing direct-adapter workload. These are controlled API cache diagnostics, not additional verified coding repairs. Append constructs declared deterministic assistant OK/user-delta history; agent preserves native generated tool history. No built-in Google tools, compaction, warming, hidden retries, resampling, endpoint substitutions, or native CLI changes. Each observation must have exactly one HTTP attempt. These adapters use nonstreaming JSON responses; raw HTTP request/response text and allowlisted response headers are retained. No SSE stream is produced or claimed.

All arms use pinned SDKs, the same frozen rate cards and normalization, low reasoning, 128 maximum output tokens, and strict-match tolerance 64. The report adds a separate 2,100-token sensitivity column without changing the original rule. Truncation/refusal and invalid tool continuation stay visible. Invalid tool continuation stops that trial; no invented tool output follows it. Arm order is shuffled with a frozen seed. Independent accounts may run concurrently, with only one trajectory at a time per key. Every trial receives a fresh nonce; this reduces cross-trial reuse without proving a backend cold start.

Report model/scenario/prefix/delta/gap cells separately, with actual initial and per-turn input, added tokens, strict64/strict2100, any-hit, weighted current-input cache share, reusable capture, theoretical follow-up input-cost multiplier, and zero-read follow-up response IDs. The cost multiplier is actual input cost divided by a declared hypothetical perfect-previous-input-reuse cost, excludes initial/output costs, and does not prove all prior tokens were eligible. Keep raw negative deficits; strict matches still require a positive cache read. Separate refusals from non-refusal measurements. Verify identical replay HTTP bodies and preserved history. Recompute all metrics offline from saved native usage.

Predeclared checks: (1) little/no Gemini reuse around 4K; (2) Flash replay versus growing history below 16,384, plus observed crossing; (3) Argon small versus large deltas and deficit sensitivity to the 2,100 rule; (4) whether input-cost impact decreases at larger starting prefixes. Five-second gaps do not test 120-second eviction or Anthropic's 300-second TTL. Those claims remain untested in this allocation. A replay discrepancy alone cannot identify routing or eviction; backend eligibility and hidden context remain alternatives.

Run the base arm through `npm run bench -- run --config config/theo-regime.json --dry-run`. The complete focused allocation is generated from qualification by `node --import tsx scripts/run-theo-regime.ts --calibration <qualification-report.json> --dry-run`, then the same command without `--dry-run`. Source commit, exact generated configs, process exits and report paths are saved in the study plan. Costs are reported from usage; no spending cutoff is imposed.
